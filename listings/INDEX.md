# Code listings

Every code block in the two books, extracted exactly as it appears on the page (comments included), one file per listing.
Each file starts with a provenance header (book, chapter, section, listing number, status, and where the compiled version lives).
Listing numbers count code blocks in book order from 0, as the 1.0 editions printed them; they are kept as stable identifiers (see the last section for the Handbook listings that no longer print in full). The compiled modules under `field-manual/` and `handbook/` are split from
these listings mechanically: they contain the listing text, with `#include`s, prototypes and a header/source split added where C needs them.

Status vocabulary: **tested** = built and checked by a test that was run (see the "Checked by" column); **compiled** = builds clean, no
behavioural test; **syntax-only** = only compiles inside a harness, or relies on definitions the book never prints;
**reference-only** = vendor HAL / CMSIS / AT-command material, archived but not built; **not-code** = formula, worksheet, procedure,
or a Python design tool (tools are in `tools/` directories and checked by `make check-generated`).
